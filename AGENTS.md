# Repository Instructions

## Mission

Maintain a trustworthy EVM wallet analyser. Correctness, reviewability, and evidence outrank speed.
These rules apply to humans and coding agents; explicit user requirements take precedence.

## Workflow

- Inspect the relevant implementation, callers, tests, configuration, and `git status` first.
- Reproduce defects before editing when practical. Fix root causes with the smallest complete patch.
- Do not invent APIs, requirements, commands, conventions, or test outcomes. State uncertainty.
- Preserve public behavior and unrelated work. No opportunistic rewrites or hidden compatibility
  layers.
- Add no production dependency, schema change, generated output, or public API change without a
  demonstrated need and explicit review.
- Keep code direct: one source of truth, explicit names, typed boundaries, and no speculative
  abstraction. Delete dead code instead of commenting it out.

## Non-negotiable domain rules

- Blockchain quantities and money are not IEEE-754 values. Preserve `bigint`, decimal strings, or
  explicit fixed-precision representations across boundaries.
- Name timestamp units and test conversions; external APIs mix Unix seconds and milliseconds.
- Validate wallet addresses and untrusted API/configuration data before database or network work.
- Never put API keys, credential-bearing URLs, wallet analysis, or full untrusted responses in
  operational logs. Explicit CLI output requested by its caller is not an operational log.
- Default tests must be hermetic: no Discord, browser, RPC, API, or database access.
- Never call TypeORM `synchronize()` in application, test, or CI code. Schema changes require a
  reviewed migration and rollback plan.
- Services own behavior; repositories own persistence. Do not introduce new imports from lower
  layers into `src/app.ts`, or from repositories back into the application bootstrap.

## Generated and sensitive files

- `src/**/index.ts` is generated by `npm run generate:index`; change source modules, then regenerate.
- `.env`, credentials, local RPC endpoints, generated wallet data, logs, and database dumps stay
  untracked. Examples contain placeholders only.
- Treat dependency, workflow, database, and authentication changes as security-sensitive. Review
  transitive dependencies and lockfile diffs.

## Verification

Use npm only (Node 22, npm 10).

```sh
npm ci                 # reproducible install
npm run check          # required before handoff
npm run check:generated
npm run audit          # required after dependency changes
```

Run the narrowest relevant test while iterating, then the full check. Never run
`npm run test:integration` without explicit permission and configured disposable services.

Before handoff: review the full diff, remove unrelated edits, and report each command as passed,
failed, or not run. A green check is required; never weaken a rule merely to make CI pass.
